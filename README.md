# TaskFlow — تطبيق مهام Flutter يعمل دون إنترنت

TaskFlow تطبيق Android مبني بـ Flutter وDart. يحفظ المهام محليًا في SQLite ولا يحتاج إلى حساب أو خادم. معرّف التطبيق المستهدف: `com.taskflow.app`.

## الميزات الموجودة

- إضافة المهام وتعديلها وحذفها وتغيير حالة الإنجاز.
- العنوان والوصف والملاحظات والفئة والأولوية وموعد الاستحقاق.
- البحث والفرز والتصفية حسب الحالة، وعرض مهام اليوم والمتأخرة والمكتملة.
- صفحة رئيسية وإحصائيات محسوبة من المهام الفعلية وتقويم شهري.
- ثيم فاتح/داكن/تلقائي وحفظ الإعدادات، واختيار اللغة العربية/الإنجليزية.
- تخزين SQLite محلي، وتصدير JSON ومراجعة بنية الملف قبل الاستيراد.
- تذكيرات محلية اختيارية، واختبارات وحدات أساسية، وسير عمل GitHub Actions لبناء APK.

## بناء APK من الهاتف باستخدام GitHub

1. نزّل `TaskFlow-Flutter-Android.zip` وفك الضغط باستخدام مدير الملفات في هاتفك.
2. افتح `github.com` في المتصفح وسجّل الدخول أو أنشئ حسابًا.
3. اضغط **New repository**، واكتب اسمًا مثل `TaskFlow`، واختر Public أو Private، ثم أنشئ المستودع.
4. افتح المستودع واضغط **Add file → Upload files**. اختر ملفات ومجلدات المشروع المفكوكة وارفعها إلى جذر المستودع. تأكد من رفع مجلد `.github` بما فيه `workflows/android-build.yml`؛ قد تحتاج إلى تفعيل إظهار الملفات المخفية في مدير الملفات.
5. اضغط **Commit changes**. سيبدأ GitHub Actions البناء تلقائيًا عند الدفع إلى `main` أو `master`. ويمكن تشغيله يدويًا من تبويب **Actions → Build TaskFlow Android APK → Run workflow**.
6. افتح تشغيل الـ workflow وانتظر انتهاء خطوات التحليل والاختبار والبناء باللون الأخضر. إذا فشل أي منها افتح الخطوة الحمراء واقرأ سجل الخطأ.
7. من صفحة التشغيل الناجح، انزل إلى **Artifacts** واضغط `TaskFlow-Android-APK` لتنزيل ZIP يحتوي APK.
8. فك ضغط الـ Artifact إن لزم، ثم افتح APK واسمح بالتثبيت من هذا المصدر عند مطالبة Android. ثبّت التطبيق.

المستودع الخاص يحمي مصدر الكود فقط؛ لا يمنع تثبيت APK الذي نزّلته بصورة مستقلة.

## متطلبات البناء المحلية

- Flutter stable حديث يدعم Dart 3.4 أو أحدث، وAndroid SDK متوافق مع نسخة Flutter المستخدمة.
- يستخدم Workflow Java 17. إذا تغيرت متطلبات Flutter/Android Gradle Plugin مستقبلًا، راجع سجلات Actions وعدّل الإصدارات المتوافقة.
- Workflow يولّد ملفات Android القياسية وGradle Wrapper عند غيابها، ثم يضبط `applicationId` و`namespace` إلى `com.taskflow.app`. ملفات Android المدرجة هي scaffold أساسي، ويعاد توليدها في CI لضمان وجود Wrapper صالح.

## التذكيرات وقيود Android

تستخدم التذكيرات إشعارات محلية مجدولة بوضع `inexactAllowWhileIdle`. قد يؤخر Android أو الشركة المصنّعة الإشعار لتوفير البطارية؛ لذلك لا يُضمن التوقيت بالدقيقة. يجب منح إذن الإشعارات على إصدارات Android التي تتطلبه. لا يحتاج التطبيق إلى اتصال بالإنترنت لتخزين المهام أو عرضها.

## البيانات والنسخ الاحتياطي

تُخزن المهام في قاعدة SQLite الخاصة بالتطبيق. تصدير JSON يفتح قائمة المشاركة لاختيار مكان حفظ النسخة. الاستيراد يضيف المهام إلى الموجودة ولا يستبدلها، ويتحقق من البنية والحقول الأساسية قبل بدء معاملة قاعدة البيانات. احتفظ بنسخة احتياطية قبل استيراد ملفات من مصدر غير معروف.

## التطوير والاختبارات

```bash
flutter pub get
flutter analyze
flutter test
flutter build apk --release
```

الاختبارات الموجودة تغطي تحويل نموذج المهمة، ونسخ حالته، وحسابات إحصائية أساسية. لم يتم التحقق من تشغيل التطبيق على جهاز فعلي من داخل بيئة إعداد هذا الأرشيف؛ يجب الاعتماد على سجل GitHub Actions لتأكيد نجاح التحليل والاختبارات والبناء النهائي.
